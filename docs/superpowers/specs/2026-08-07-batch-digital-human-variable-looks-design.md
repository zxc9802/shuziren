# 批量数字人可变造型工作流设计

## 目标

为 15–90 秒中文数字人口播建立可排队、可恢复的生产流程。每条视频保持同一个老板身份和固定克隆声音，但允许服饰、姿势、背景、灯光和构图随当次文案变化。所有 HeyGen 实际操作只使用已登录付费账户的套餐额度，不使用 API key 或 API credits。

## 固定资产与派生资产

- `图片1` 是不可替换的老板身份母图。它锁定脸型、年龄、肤色、发型、眼镜和整体辨识度。
- `声音1` 是固定克隆声音。所有任务复用同一稳定声音身份，但语速、停顿、重音和语气由当次文案决定。
- `老板身份组` 保存图片1以及以后所有获批的新造型。
- `任务造型` 是从图片1派生的单条任务图片。它可以改变服饰、姿势、背景、灯光和构图，但不能改变身份特征。
- 所有获批任务造型按任务命名并永久保留，便于复用和追溯。

## 单条任务流程

1. 接收当次文案，分析时长、语气、节奏、语义重音和动作重点。
2. 每条任务都询问：是否调用内置生图模型生成新的老板形象。
3. 用户选择不生成时，始终使用原始图片1；不得沿用上一条任务的派生造型。
4. 用户选择生成时：
   - 使用图片1作为身份参考；
   - 根据当次文案自动规划服饰、姿势、背景、灯光和构图；
   - 默认只生成一张候选图；
   - 将候选图交给用户审核；
   - 只有用户针对该图明确回复“采用”后才能继续；
   - 不满意时只按反馈重新生成图片；
   - 获批图片保存到老板身份组并按任务命名。
5. 询问本条任务是否需要 15 秒低成本预览，并记录独立回答。
6. 使用选定形象、声音1和当次完整文案制作 Avatar IV、9:16、720P 数字人口播。
7. 预览确认只授权继续生成完整原片。
8. 完整原片通过 QA 后单独交付，并绑定视频 ID 和文件指纹等待明确批准。
9. 只有完整原片获批后才能进入 HyperFrames 后期制作。

## 套餐额度执行方式

套餐额度模式通过已登录的 HeyGen 网页完成实际操作，不使用需要 API credits 的独立语音或视频接口，也不把 Video Agent 的方案草稿当作渲染任务。

在扣除视频生成额度前，自动完成并验证：

- 上传或选择本任务已确认的老板形象；
- 选择稳定声音1，而不是仅按同名声音猜测；
- 写入逐字一致的完整中文文案；
- 设置 Avatar IV、9:16、720P；
- 关闭字幕、背景音乐、B-roll、镜头切换和缩放；
- 写入完整动作约束；
- 确认页面中的虚拟形象不为空；
- 确认目标时长没有被方案层擅自改变。

完成上述检查后，浏览器自动点击真正的“生成”按钮。用户无需再次手动选择形象或点击生成。

## 表演与动作约束

每条任务从语义表演计划生成完整动作指令，并在真实提交前验证该指令没有被方案层丢失：

- 镜头和构图全程固定；
- 目光自然，眨眼不规则但克制；
- 表情跟随句意和语气变化；
- 头部动作小幅、短促，并与短语重音一致；
- 肩膀和躯干稳定，避免持续摇晃；
- 只有源图手部拓扑允许时才使用手势；
- 一次只完成一个语义明确的手势循环；
- 每次手势后完整回到静止位；
- 不允许推拉、缩放、切镜、重复摆动或无意义持续动作。

## 真实生成判定

工具返回的成功文案不是生成证据。只有满足至少一项才允许向用户报告“正在生成”：

- HeyGen 状态进入 `generating` 或 `completed`；
- 出现可查询的真实视频任务；
- 页面明确进入真实渲染进度状态。

以下状态只能标记为“方案已创建”或“等待绑定”，不得标记为正在生成：

- 只有 blueprint、draft 或视频方案；
- `thinking` 且 `progress=0`；
- 当前会话视频列表为空；
- 页面仍显示待点击的“生成”按钮；
- 虚拟形象位置为空；
- 连接器只返回 `started successfully` 文案。

点击生成后立即复查页面和任务状态。状态不明确时继续查询现有任务，禁止重复点击或重新提交。

## 批量队列与状态

多条文案可以一次入队，但默认顺序执行，避免多个任务同时操作同一个 HeyGen 网页导致形象、声音或文案串单。一条任务等待图片、预览或原片确认时，未开始的任务保持排队。

单条任务状态：

```text
planned
-> image_generation_choice_recorded
-> awaiting_image_approval        # 仅选择生图时
-> image_approved
-> preview_choice_recorded
-> preview_rendering
-> awaiting_preview_approval
-> full_raw_rendering
-> awaiting_raw_approval
-> post_production
-> complete
```

审批证据不得跨任务或跨资产复用：

- “采用”只批准当前候选图片；
- 预览确认不批准完整原片或后期；
- 完整原片批准必须绑定 reviewer、时间、证据引用、视频 ID 和 SHA-256；
- 以前任务中的“采用”“继续”“确认”不适用于新任务。

## 失败恢复

- 生图不满意：只重新生成候选图。
- 图片上传失败：重试同一已批准图片，不重新生图。
- HeyGen 只生成蓝图：继续完成形象绑定和真实提交，不创建重复任务。
- 已出现真实视频 ID：只轮询该 ID。
- 网页结构变化：保存当前状态并明确报告卡点，不谎报生成、不重复扣费。
- 文案、声音、形象、时长或动作配置不一致：在扣除视频额度前停止。
- 临时下载地址过期：重新查询同一视频任务，不重新渲染。

## 验证标准

自动测试和任务级检查必须覆盖：

- 不生图时始终回退到原始图片1；
- 生图时未获得针对当前图片的“采用”不得继续；
- 新图保持老板身份不变，但允许服饰、姿势、背景变化；
- 获批造型保存到同一身份组并可追溯；
- 正确绑定稳定声音1和当次逐字文案；
- 语速、停顿、重音根据文案变化；
- 动作提示完整进入最终生成配置；
- 蓝图和 `thinking/progress=0` 不会误报为生成；
- 真实生成只提交一次，轮询和下载不会触发重复扣费；
- 批量任务不会串形象、声音、文案或审批；
- 15–90 秒、9:16、720P、Avatar IV、固定镜头和审批门正确执行。

## 非目标

- 不自动批准新形象、预览或完整原片。
- 不自动沿用上一条任务的派生造型。
- 不使用 MiniMax、HeyGen API key、直接 HTTP 或 API credits。
- 不在完整原片获批前启动 HyperFrames。
