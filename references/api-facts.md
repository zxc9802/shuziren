## Browser submission settings

The default raw contract is Avatar IV, portrait `9:16`, `720P`, fixed camera, no captions, no music, no B-roll, and no transitions. Paste the exact script and retain the complete semantic voice/motion directions.

The browser agent must verify the visible bound avatar thumbnail, exact voice identity, script text, orientation, resolution, engine, extras, and motion prompt before spending. It then clicks Generate once.

## Evidence classifier

Return only:

- `blueprint_ready`: thinking at zero progress or a blueprint/draft resource;
- `blocked`: missing binding, missing video, visible Generate button, malformed state, or failed submission;
- `rendering`: real video resource with stable ID, bound avatar, nonzero progress, nonempty video list, and hidden Generate button;
- `completed`: the same real evidence plus completed status and full progress.

Never trust a success-message string by itself. A plan, connector connection, chat statement, or visible draft is not a render.

## Volatile facts

Pricing, balances, page layout, labels, and available controls may change. Inspect the logged-in page at runtime. Use accessibility roles and visible labels instead of hard-coded CSS selectors. Never hard-code a historical balance or price, and never switch to API credits when a web control changes.
